Conceitos Fundamentais

Entenda os termos e definições essenciais do Split de Pagamento Zoop

🔑 Definição Central

Split de Pagamento é a tecnologia que automatiza a divisão de um único pagamento entre múltiplos recebedores, com base em regras configuradas pelo marketplace.

💡

A Zoop processa a transação e distribui os valores automaticamente, eliminando a necessidade de transferências manuais entre contas.

🧩 Terminologia Chave
TermoTipoDescrição
on_behalf_ofstringSeller dono da venda
split_rulesarrayLista de regras de divisão
recipientstringID do recebedor
liablebooleanQuem responde pelas cobranças
charge_processing_feebooleanSe cobra taxa de processamento
amountintegerValor em centavos a repassar
🔁

Como Funciona o Fluxo

Passo a passo desde a transação até a liquidação

1

Cliente realiza o pagamento

O comprador efetua a transação no marketplace (cartão, Pix, boleto, etc.).

2

Zoop processa a transação

A transação é aprovada e o valor total fica retido na plataforma Zoop.

3

Regras de split são aplicadas

A priori: já enviadas junto com a transação. A posteriori: enviadas após a aprovação, até D-1.

4

Liquidação e distribuição

Na data de liquidação, os valores são distribuídos automaticamente para cada recebedor conforme as regras configuradas.

⚠️

Atenção Regulatória: Alguns usos do split podem caracterizar desvio de função. Sempre valide com as áreas de Jurídico, PLD e Compliance antes de implementar casos fora dos padrões listados.

🔀

Tipos de Split

Entenda a diferença entre split a priori e split a posteriori

🔵 Split A Priori

"Antes" da transação

Online

As regras de divisão são enviadas junto com a requisição da transação, no mesmo request. Ideal quando o marketplace já conhece todos os participantes no momento da venda.

✅

Quando usar: marketplace já sabe os participantes no momento da compra

🌐

Ambiente: principalmente transações online

🔄

Alteração: pode ser modificado antes da liquidação via split a posteriori

🚫

Exceção: Boleto com Pix não suporta split a priori

🟠 Split A Posteriori

"Depois" da transação

Online + Físico

As regras são enviadas após a aprovação da transação, em endpoint separado. Único formato para mundo físico. Regras podem ser alteradas até D-1 da liquidação.

✅

Quando usar: mundo físico, Tap to Pay, ou para alterar split inicial

🏪

Ambiente: online e físico (único disponível no físico)

📅

Prazo: regras enviadas/alteradas até D-1 da liquidação

👥

NPP: na nova plataforma, comissionamento aceita apenas 2 participantes

📊

Na Prática — API

Exemplos reais de chamadas e campos utilizados na integração

🔵 Split A Priori POST na transação com split_rules incluso

Estrutura do Payload

Envie as split_rules dentro do body do POST de criação da transação:

JSON PAYLOAD — Split A Priori
// POST /v1/marketplaces/{marketplace_id}/transactions { "on_behalf_of": "seller_123abc", // ID do seller (dono da venda) "description": "Pedido #4567", "currency": "BRL", "amount": 10000, // R$ 100,00 em centavos "payment_type": "credit", "split_rules": [ { "recipient": "marketplace_456def", // recebedor (marketplace) "liable": false, // quem responde pelas cobranças "charge_processing_fee": true, // cobra taxa de processamento "amount": 1000 // R$ 10,00 de comissão } ] }
🟠 Split A Posteriori POST separado após aprovação da transação

Endpoint e Payload

Após a transação ser aprovada, envie as regras de split em endpoint dedicado:

URL — Split A Posteriori
// POST em endpoint separado: POST /v1/marketplaces/{marketplace_id}/transactions/{transaction_id}/split_rules
JSON PAYLOAD — Split A Posteriori
{ "recipient": "marketplace_456def", // recebedor da comissão "liable": false, "charge_processing_fee": true, "amount": 1500 // R$ 15,00 }
📋 Descrição dos Campos split_rules
CampoTipoObrigatórioDescrição
recipientstring Sim ID do recebedor (marketplace ou seller)
liableboolean Sim Define quem é responsável por estornos e chargebacks. Geralmente o seller.
charge_processing_feeboolean Sim Define se esse participante paga a taxa de processamento da transação.
amountinteger Sim Valor em centavos a ser repassado para o recipient.
ℹ️

Prazo de alteração: As regras de split a posteriori podem ser enviadas e modificadas até D-1 da data de liquidação da transação. Após essa data, não é possível alterar.

Aspectos Regulatórios

O que o time de CX precisa saber sobre compliance

!

Desvio de Função

Alguns usos do split podem caracterizar desvio de função financeira. Sempre valide casos atípicos antes de orientar o cliente.

!

Sub-recebimento

O split da Zoop foi desenvolvido para evitar o sub-recebimento irregular. Qualquer configuração que possa caracterizar isso deve ser validada com Compliance.

!

Áreas a Envolver

Para casos fora do padrão: Jurídico + PLD + Compliance. Não oriente o cliente antes desta validação interna.

NPP — Nova Plataforma Única

O futuro do Split de Pagamento na Zoop

⚠️

Status Atual: As diretrizes da NPP para split ainda estão sendo definidas. Não há um direcional definitivo. Analise caso a caso e envolva o time de Produtos quando necessário.

📌 O que é a NPP

A Nova Plataforma Única (NPP) é a nova infraestrutura da Zoop que unificará todos os produtos de pagamento. Os produtos Online estão sendo migrados para NPP, e novos formatos de split serão desenvolvidos.

🏗️

Migração dos produtos Online para NPP

🔀

Novos formatos de split a posteriori em desenvolvimento

👥

Inicialmente: split de comissionamento com apenas 2 participantes

📱 Tap to Pay (Nubank)

Desenvolvido especialmente por demanda do Nubank, o Tap to Pay ganhou formatos específicos de split:

🔵

Novo split a priori — desenvolvido especificamente para Tap to Pay

🟠

Split a posteriori de comissionamento — apenas 2 participantes (marketplace + seller)

💡

Modelo que tende a se tornar padrão na NPP

📅

Linha do Tempo NPP

Evolução do Split na nova plataforma

Split Legado — Plataforma Atual

Split a priori e a posteriori disponíveis para transações online. Split a posteriori exclusivo para mundo físico. Até 20 movimentações por transação.

Tap to Pay (Nubank) — Novo Formato

Desenvolvimento de split a priori exclusivo e split a posteriori de comissionamento com 2 participantes (demanda Nubank). Modelo que serve de referência para NPP.

NPP — Migração dos Produtos Online

Transação dos produtos online para a Nova Plataforma Única. Adaptação dos formatos de split existentes. Regras e prazos em revisão por questões regulatórias.

NPP — Split a Posteriori Adaptado

Tendência: split a posteriori de comissionamento limitado a 2 participantes inicialmente. Possível expansão futura conforme definição regulatória e de produto.

Direcional Definitivo NPP

Definição final das regras, formatos e prazos do split na NPP. Envolver time de Produtos para casos não convencionais até essa definição.

📌

Orientação para o time de CX: Enquanto o direcional definitivo da NPP não é publicado, analise cada caso individualmente. Para situações que fogem do padrão (comissionamento simples), envolva o time de Produtos internamente antes de orientar o cliente.
